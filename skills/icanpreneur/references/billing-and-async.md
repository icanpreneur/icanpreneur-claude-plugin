# Credits and asynchronous work

## Starting credit gates and charges

| Tool                                                                                 | Behavior                                                                                                                                                                                                                                                     |
| ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `create_idea`                                                                        | Positive starting balance required; the initial Canvas is created during the call. Read its saved contents after success; logo work may continue.                                                                                                            |
| `validate_canvas_item`                                                               | Billable advisory check, despite looking like a read.                                                                                                                                                                                                        |
| `create_canvas_customer_segment`                                                     | Positive starting balance required; automatic linking of other Canvas items can use credits and continue after the response.                                                                                                                                |
| `create_canvas_item`                                                                 | Positive starting balance and automatic association when `relatedItemIds` is omitted or `[]`. Only a nonempty explicit segment-ID array skips association. Use `update_canvas_item` with `[]` to clear links afterward.                                        |
| `generate_interview_script`                                                          | Billable script generation.                                                                                                                                                                                                                                  |
| `create_research`                                                                    | Requires positive balance when type is `BuyerPersona` OR `generateSyntheticInterviews` is true. Only BuyerPersona research creates a persona; an empty persona can be Complete without generated content. The flag starts exactly five synthetic interviews. |
| `generate_synthetic_interviews`, `generate_synthetic_contacts`                       | Billable synthetic generation; positive balance required.                                                                                                                                                                                                    |
| `import_interview`, `import_interviews`                                              | Positive balance required. Each saved import is charged before analysis starts; analysis adds charges. A failed batch may have saved and charged some files.                                                                                                 |
| `ask_buyer_persona`                                                                  | Every question is billable, including follow-ups.                                                                                                                                                                                                            |
| `generate_positioning_and_messaging`, `generate_landing_page`, `generate_sales_deck` | Billable document generation.                                                                                                                                                                                                                                |
| `generate_buyer_persona_document_preview`                                            | Billable rendering, including regeneration.                                                                                                                                                                                                                  |

`create_interview` saves a NotStarted interview without a direct charge. `update_interview` edits only NotStarted standard interviews and has no direct charge. Their events can update research state. Interview delivery is charged when it actually starts; completed interviews start billable insight/quality processing. `update_research_interviews` can start insight extraction for a newly encountered research type and refresh aggregate analysis and personas. `delete_interview` and `restore_interview` can refresh research/personas. These calls have no explicit positive-balance gate in the MCP controller; automatic follow-on work can use credits.

Other manual edits, duplicates, uploads, notes, invitations and membership changes have no direct AI-credit charge. Reads/exports have no direct charge; some underlying services can launch repairs of stuck generated work. Do not promise that every read is free of all possible background effects.

Before the first user-initiated billable call, check `get_ai_credit_balance`. At zero or below, do not start; explain that a positive AI-credit balance is required. An admitted operation can finish below zero. A snapshot is not a reservation; recheck after a long gap or material spending.

The MCP gate returns `code: INSUFFICIENT_AI_CREDITS`, `message` and `balance`. Other license/permission failures can also occur. There is no per-call charge/balance success envelope or `safeToRetry` field. `list_ai_credit_costs` gives operation tariffs, not a complete workflow quote. Before/after balances are shared-pool snapshots, not attributable per-call charges. Automatic interview/research processing can bill the creator or host selected by the service, rather than always the current caller.

| ------------------------ | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

A timeout/error can leave a saved workspace: inspect `list_ideas` and `get_canvas` before any retry. |

Use a bounded number of reads with brief delays. If work is still pending, provide resource IDs and the next read. Never repeat a mutation just to check progress, promise monitoring, or silently use a stale result after a requested refresh fails.

## Analysis state and freshness

Research MCP reads select the latest analysis record. Pending/Error can expose empty or partial new results; they do not guarantee the previous completed snapshot. Before the first research analysis exists, a 404 means there is no analysis to read yet. `updatedOn` on analysis and persona records is a modification timestamp, including processing/manual changes; it is not a guaranteed completion timestamp.

Compare the analysis `interviewCount` with current research membership, but equal counts do not prove the same interviews were included. Membership counts also include unfinished interviews, while analysis uses eligible completed interviews. Read newly added interviews' analysis and report uncertainty when inclusion cannot be verified. The API does not expose immutable analysis/version provenance. Insight categories and quality are returned in full, without paging. Separate calls are not an atomic snapshot; if state changes while reading, refresh before combining conclusions.

Quality is typically a 0–100 score of how interviews were conducted; coverage is typically a 0–100 percentage of script lines covered. Research summaries average included interview values. Report the saved value and explanation, without invented thresholds. `percentageImprovement` ranks estimated improvement potential; it is not a measured percentage or evidence confidence.

## Interview insight types and membership changes

An interview has one analysis record with insight categories/sub-statuses per research type, not an independent complete analysis per project. A newly encountered type triggers extra insight extraction; results for that type are cached and reused. Interview quality and script coverage are shared. Aggregate research analysis remains separate for every research.

Removing an interview only changes membership; it can refresh or clear that research's aggregate analysis and refresh its BuyerPersona. It does not delete the interview or cached type-specific insights. With no eligible interviews the aggregate can be cleared and the persona can become empty. Existing persona documents and previews are not regenerated.

## Persona use and conversation versions

- For a build you just requested, wait for Complete and populated content before dependent work. A transient Complete empty record after research creation does not mean a build finished.
- Existing Pending/Error persona fields may reflect older or incomplete content. They are not guaranteed to be an independently selectable completed version. `generate_positioning_and_messaging` rejects anything except a Complete, nonempty source. Wait or report the block.
- Asking a persona has no identical Complete gate in the controller. If a usable profile exists, an existing conversation may still answer; disclose the state and stop on failure. Never fill in the persona's answer yourself.
- Persona answers are always simulated. Conversation IDs, `buyerPersonaVersion` and `usesLatestPersona` are returned by `ask_buyer_persona`. Follow-ups retain conversation context. Do not promise an immutable historical persona snapshot: version is the entity's revision, and the API does not return the interview set used by that answer.
- To start fresh, omit `conversationId`. There is no conversation-listing tool; a lost ID cannot be recovered through MCP. An uncertain question must not be retried automatically.
